第六轮全项目审计后的追加修复轮次，专注解决三个被遗漏的关键问题：wasm-edge 全部 `static mut EVENTS` 反模式、deploy.sh 18MB 乱码、Agent 端到端可用性验证。

### 10.1 wasm-edge `static mut EVENTS` 反模式全量修复（7 个文件）

**问题类型**：进程级单例共享状态 + Rust 内存安全违规

**问题描述**：`wifi-densepose-wasm-edge` crate 中 7 个 WASM 模块使用 `static mut EVENTS: [(i32, f32); MAX_EVENTS]` 作为事件缓冲区，所有 tracker 实例共享同一块内存，导致：
- 多实例并行运行时事件数据相互覆盖（数据竞争）
- `process_frame()` 返回值 `&'static [(i32, f32)]` 绕过生命周期检查，调用方可能在数据被覆盖后仍使用旧引用
- 大量 `unsafe` 块违反 Rust 内存安全原则

**修复方案**：

1. 每个 tracker 结构体新增实例字段 `events_buf: [(i32, f32); MAX_EVENTS]`
2. `new()` 中初始化为 `[(0, 0.0); MAX_EVENTS]`
3. 所有 `unsafe { EVENTS[i] = (event_id, value); }` 替换为 `self.events_buf[i] = (event_id, value);`
4. 所有 `unsafe { &EVENTS[..ne] }` 替换为 `&self.events_buf[..ne]`（生命周期绑定到 `&self`）
5. 删除 `static mut EVENTS` 声明
