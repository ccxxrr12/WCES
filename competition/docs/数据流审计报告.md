## 概览：3 层、12 条主线

```
ESP32-C5 ×3  ──UDP:5005──>  RZ/G2L (Rust)  ──WebSocket:8765──>  浏览器
                                 │
                                 └── HTTP:8080 (静态UI + REST API)
```

---

## 第一层：ESP32-C5 感知节点 → UDP 上行

WiFi CSI 帧通过 ESP32-C5 的**正常 STA RX 模式**采集（非 promiscuous——C5 单射频半双工下 sniffer 会阻塞 TX）。STA 模式下信道由 AP 分配，`esp_wifi_set_channel()` 信道跳转在已连接状态下静默失效。三节点均锁定在 AP 的工作信道上。

### 数据采集

```
CSI 帧到达 (HE SU: 242/484 子载波 | HT40: 114 | HT20: 56 | L-LTF: 52)
  │
  ├─ csi_collector.c: wifi_csi_callback()
  │    ├─ AGC Gain Lock: 前 300 帧学习基线 → 锁定 AGC → 动态范围 3dB→4.3dB
  │    ├─ 信道跳转: 6ch × 50ms dwell (STA 模式下静默失效, 信道由 AP 锁定)
  │    ├─ 速率限制: 20ms (50Hz max) 发送间隔, 防止 lwIP pbuf 耗尽
  │    ├─ SO_SNDTIMEO=100ms 防止 ARP 阻塞 WiFi 任务
  │    └─ UDP sendto() → RZ/G2L:5005
  │
  ├─ edge_processing.c (片上边缘预处理)
  │    ├─ Biquad IIR 带通滤波 (呼吸 0.1-0.5Hz, 心率 0.8-2.0Hz)
  │    ├─ NaN/Inf 防护 + 参数范围校验 (fs>0, f_lo<f_hi, 满足 Nyquist)
  │    ├─ 相位提取 + 解卷绕 + 运动能量 + 存在检测
  │    └─ 打包为边缘生命体征包 (magic 0xC511_0002, 固定 32 字节)
  │
  └─ 3 种上行包类型:
       ├─ CSI 原始帧      (0xC511_0001)  ← 主力数据, 20B 头 + I/Q 对
       ├─ 边缘生命体征     (0xC511_0002)  ← 低带宽备选, BR/HR/运动/存在
       └─ WASM 边缘事件   (0xC511_0005)  ← C5 端 WASM3 已禁用; 实际由 RZ/G2L 原生 Rust 运行
```

### 容错机制

| 机制 | 位置 | 说明 |
|------|------|------|
| UDP 发送失败重启 | main.c | sendto init 失败 → esp_restart() |
| WiFi 断线重连 | main.c | 指数退避 500ms×retry, 6 种永久失败 reason 检测 |
| 密码 null 终止 | main.c | strncpy 后显式 `\0` |
| 环形缓冲区溢出 | csi_collector.c | 4096 次丢弃记一次 warning 日志 |
| 信号量超时 | csi_collector.c | 100ms 超时 → warning, 跳过当次跳转 |

## 第二层：Rust 服务端 — 每帧处理管线

服务端由 `udp_receiver_task` 驱动，每收到一个 UDP 帧执行三个阶段：写锁内状态变更（Phase 1）、无锁纯计算（Phase 2）、写锁内广播（Phase 3）。

### Phase 1: 写锁内 — 每节点独立管线

持有 `state.write()` 锁，操作 `s.node_states[frame.node_id]` 的 PerNodeState。

```
frame.amplitudes + frame.phases
  │
  ├─ [1] 动态采样率测量
  │       dt = now - ns.last_frame_time → 瞬时频率 1/dt → EMA(α=0.15) → ns.measured_sample_rate
  │       替代硬编码 20Hz, 自适应 ESP32-C5 实际发送速率 (10-100Hz)
  │
  ├─ [2] SignalPipeline.process()              ← wifi_densepose_signal crate
  │       PhaseSanitizer(相位展开+异常值移除) → HardwareNormalizer
  │       → HampelFilter(中值滤波) → MotionDetector(自适应阈值)
  │       → CoherenceState + GatePolicy(信号质量门控)
  │       产出: SignalPipelineOutput { motion_score, human_detected,
  │              gate_allows_update, coherence_score, cleaned_amplitudes, cleaned_phases }
  │       消费: motion_score → 运动分类; cleaned_amplitudes/phases → VitalsBridge 输入
  │
  ├─ [3] extract_features_from_frame()
  │       四维特征: 帧间差(0.4) + 方差(0.2) + 频带功率(0.25) + 变化点(0.15)
  │       产出: FeatureInfo { mean_rssi, variance, spectral_power,
  │              dominant_freq_hz, motion_band_power, breathing_band_power, sub_variances }
  │
  ├─ [4] 运动分类 (仅使用 signal_pipeline 的 motion_score)
  │       motion_score → EMA(α=0.15) → 阈值判定:
  │       >0.15 "active" | >0.08 "present_moving" | >0.03 "present_still" | else "absent"
  │
  ├─ [5] VitalsBridge.extract()               ← IIR 带通 + 零交叉 + 自相关
  │       EMA 预处理(静态分量抑制) → IIR 带通滤波(Butterworth 型)
  │       → 零交叉计数 (呼吸率, 30s 窗口) + 自相关峰值 (心率, 15s 窗口)
  │       输入: signal_pipeline 的 cleaned_amplitudes/phases (可用时) 或原始 frame 数据
  │       产出: breathing_rate_bpm, heart_rate_bpm, br_confidence, hr_confidence
  │       signal_quality 由两通道置信度的 max 值推算 (BUG 46 修复: 之前因 FFT 路径移除而固定为 0)
  │
  ├─ [6] CIRBridge.process()                   ← ISTA 稀疏 CIR 估计
  │       频域 CSI → ISTA 迭代软阈值(L1 正则化) → 时域多径抽头
  │       → dominant_distance_m / ranging_distance_m (ToF 测距, c×τ)
  │       产出: cir_distance_m (供 LocalizationBridge 使用, ToF 距离 3× 权重)
  │
  ├─ [7] FieldBridge.feed()                    ← SVD 空房间电磁场校准
  │       前 600 帧(~30s@20Hz): feed_calibration → Welford 协方差累积 → SVD 分解
  │       校准完成后: 减空房间基线 → 投影到环境模式正交补 → perturbation.total_energy
  │       → 50 帧 EMA 平滑 → 产出 field_perturbation (注入 signal_field.values 热力图)
  │
  ├─ [8] TriageEngine.process()                ← START 分诊引擎
  │       输入: VitalSignsInput { BR, HR, 置信度, signal_quality, motion_score,
  │              node_id, rssi, person_id }
  │       伤员匹配: 余弦相似度 (阈值 0.65) → 8 维生物特征嵌入
  │       START 判定: Immediate(红)/Delayed(黄)/Minor(绿)/Deceased(黑)/Unknown(灰)
  │       产出: TriageUpdate { survivors: [{id, triage, position, breathing_rate, heart_rate}] }
  │
  ├─ [9] EdgeModuleEngine.process_frame()      ← 10 个边缘分析模块
  │       模块: gait, loitering, vibration, ltl, meta_adapt, sparse_recovery,
  │             vital_trend, attractor, coherence, resp_distress, confined_space,
  │             panic_motion, sleep_apnea, cardiac, seizure, intrusion, occupancy,
  │             mincut, weapon_detect (共 19 个注册, 竞赛启用 10 个)
  │       输入: phase_f32, amp_f32, raw_motion, BR, HR, presence
  │       产出: Vec<EdgeAlert> { module, event_name, severity, value }
  │
  ├─ [10] LocalizationBridge + TrackingBridge  ← 辅助定位
  │       LocalizationBridge: 多节点 RSSI + CIR ToF → 加权最小二乘三角定位
  │                           失败回退到 CIR 加权质心 (CIR 距离 3× 权重)
  │       TrackingBridge: 6-D Kalman (CV 模型, Joseph 协方差更新)
  │                       + 马氏距离关联门控 + 8 维 CSI 指纹重识别
  │                       + lost_pool 5min → 三级匹配 (person_id→Re-ID→新建)
  │       注意: 此处产出的 survivor.position 在 Phase 2 被混合质心覆盖
  │
  ├─ [11] AlertingBridge.generate_alert()      ← 结构化告警
  │       触发条件: triage ∈ {Immediate, Delayed, Deceased}
  │       产出: AlertInfo { id, survivor_id, title, priority, status }
  │       入队: generated_alerts (FIFO, 最大 50 条)
  │
  └─ [12] 其他写锁内操作:
           • LLM push_vitals: 将 vitals 快照推入 LLM Engine 的滑动窗口 (clone Arc, 释放锁后 await)
           • 自适应模型覆盖: adaptive_override() (仅当训练好的分类器加载时)
           • 跨节点快照: 收集所有活跃 node_id 的最新 RSSI/BR/HR/运动状态
```

### Phase 1 衔接: LLM Agent 异步触发 (写锁外)

```
锁外操作 (udp_receiver.rs:402-537):
  ├─ LLM push_vitals: 调用 llm_engine.push_vitals(BR, HR, motion, signal_quality).await
  │    将 vitals 数据推入 MedicalAgent 的滑动窗口 (1min/5min)，<2ms 持锁
  │
  └─ Agent 恶化触发: 当 triage 级别上升 (Minor→Delayed→Immediate→Deceased) 时
        ├─ 构造 StructuredContext { vitals, trends, triage, alerts, kb_matches }
        ├─ tokio::spawn 异步任务 (Semaphore 限流 4 并发, timeout 30s)
        ├─ MedicalAgent.analyze(ctx).await → LLM 流式分析 / 本地模板降级
        └─ 结果通过 broadcast channel → WebSocket "agent_analysis" 消息
```

### Phase 2: 无锁纯计算

写锁已释放，仅使用 Phase 1 提取的数据。

```
  ├─ generate_synthetic_pose()                  ← 合成 3D 骨架 (17 COCO 关键点)
  │       输入: tick, frame.amplitudes, motion_score → 无 ML 模型
  │
  ├─ generate_signal_field()                    ← 20×20 信号场热力图
  │       输入: rssi_mean, motion_score, breathing_rate_hz, signal_quality, subcarrier_variances
  │       field_perturbation 注入: 每 cell 值 += (perturbation × 0.3).clamp(-0.5, 0.5)
  │       产出: SignalField { values: [f64; 400] }
  │
  ├─ **主定位: 子载波方差 + 相位差分混合加权质心**
  │      子载波方差通道 (60%): Top-12 子载波振幅方差均值
  │        → 自适应基线归一化 (node_max 指数衰减 0.9995/帧, ~10s 回落到环境水平)
  │        → var_prox ∈ [0, 1]
  │      相位差分通道 (40%): 帧间 |ΔPhase|/π → phase_prox ∈ [0, 1]
  │      融合: prox = 0.6×var_prox + 0.4×phase_prox
  │        → EMA 平滑 (α=0.12) → node_prox[node_id]
  │      多节点平方权重质心:
  │        P_centroid = Σ(prox[i]² × N_i) / Σ(prox[i]²), 权重阈值 >0.005
  │        pos_conf = (Σw² / 0.5).clamp(0.15, 1.0)
  │      多伤员交错: P_i = P_centroid + stagger_i (1.2m 错开)
  │      **覆盖 TriageUpdate.survivors[].position** (覆盖 Phase 1 的 Kalman/三角定位结果)
  │
  └─ derive_pose_from_sensing()                 ← 人员检测
         输入: SensingUpdate → 输出: Vec<PersonDetection> (写入 update.persons)
```

### Phase 3: 写锁内 — 广播

```
SensingUpdate 组装与发送 (throttled to 10Hz, BROADCAST_INTERVAL_MS=100):
  {
    type:           "sensing_update",
    timestamp:      f64,
    source:         "esp32",
    tick:           u64,
    nodes:          Vec<NodeInfo>,       // 所有活跃节点快照 (含 BR/HR/RSSI/位置/振幅)
    features:       FeatureInfo,         // 7 维信号特征
    classification: ClassificationInfo,  // 运动级别 + 存在检测 + 置信度
    signal_field:   SignalField,         // 20×20 热力图 (含 field_perturbation 注入)
    vital_signs:    Option<VitalSigns>,  // 呼吸/心率/置信度/信号质量
    triage_update:  Option<TriageUpdate>,// START 分诊 + 伤员列表 (位置已被主定位覆盖)
    wasm_alerts:    Option<Vec<EdgeAlert>>,
    tracked_survivors: Option<Vec<TrackedSurvivor>>, // Kalman 追踪快照
    pose_keypoints: Option<Vec<[f64;4]>>,
    persons:        Option<Vec<PersonDetection>>,
    estimated_persons: Option<usize>,
    alerts:         None,                // 由 broadcast_tick_task 单独推送
  }
    │
    └─ s.tx.send(json) → tokio::sync::broadcast (容量 1024)
       s.latest_update = Some(update)   // 即使不广播也更新缓存, 供 broadcast_tick 重播
```

## 审计结论

- **编译状态**: 0 errors, ~247 warnings (预存 dead_code/cfg_attr, 不影响运行)
- **数据流完整性**: 12 条路径全部接入, 0 条遗漏
- **冗余已消除**:
  - 三重生命体征 → 单一 VitalsBridge (IIR 带通 + 零交叉 + 自相关)
  - 双运动检测 → 仅用 signal_pipeline
  - VitalSignDetector (FFT+Goertzel) 已移除
  - DetectionBridge (MAT crate) 已移除
- **死数据流已接线** (2026-07-02):
  - signal_pipeline.cleaned_amplitudes/phases → VitalsBridge 输入
  - field_bridge.perturbation → signal_field.values 热力图
  - tracking_bridge Kalman 快照 → SensingUpdate.tracked_survivors
  - alerting_bridge.drain_alerts() → broadcast_tick → WebSocket
- **2026-07-07 修正**:
  - 定位基线: node_max 固定峰值 → 指数衰减 (0.9995/帧), 消除瞬态扰动永久压制邻近度
  - 节点坐标: 硬编码 2m 等边三角形 → 参数化边长 (mat_pipeline.rs side 参数, 按实际部署调整)
  - 信道跳转: 标注 STA 模式限制 (esp_wifi_set_channel 静默失效), 三节点同信道工作
  - CSI 子载波: 区分 HT 格式 (56/114) 与 HE-SU 格式 (242/484), 主力为 HE-SU
  - 定位架构: 明确三层优先级 — 主定位 (混合质心, Phase 2 无锁) 覆盖辅助定位 (Kalman/三角定位, Phase 1)
  - 信号质量: 修复 BUG 46, VitalsBridge 置信度正确传导至 signal_quality
- **前端全覆盖**: 8 种 WebSocket 消息类型全部路由到渲染函数
